# Parallel Task Orchestrator

## Summary
Break a project or goal into 5 to 10 internal subtasks executed conceptually in parallel tracks, then present the final output focused on clean task formatting and parallel coordination.

## When to Use
- The user provides a project, idea, or goal to break down and organize.
- The user asks to coordinate tasks, structure subtasks, or plan parallel execution.
- The user wants a clean, formatted task breakdown without verbose intermediate analysis.

## Steps
1. Internally decompose the request into 5 to 10 concrete subtasks without narrating raw brainstorming.
2. Group or tag subtasks into parallel tracks where steps can advance concurrently, noting dependencies only when one subtask strictly blocks another.
3. Format the final response around clean task organization (such as grouped parallel tracks, tables, or structured lists) so the user can act on tasks immediately.
4. Keep wording concise and action-oriented, avoiding filler or long preambles.

## Gotchas
- Keep the total subtask count strictly between 5 and 10; merge tiny steps or split broad ones to stay in range.
- Do not force sequential order when subtasks are independent and can progress in parallel.
- Focus the visible output on formatted tasks and parallel structure rather than meta-commentary about the skill.
